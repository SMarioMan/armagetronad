# Armagetron Advanced in the browser (WebAssembly + WebGL)

The `webgl` branch runs Armagetron Advanced 0.2.9.3.0 as a WebAssembly module
in the browser: SDL1 through emscripten's JS port, the game's fixed-function
OpenGL pipeline through emscripten's legacy GL emulation, and every data file
preloaded into the virtual filesystem.

Live site: <https://smarioman.github.io/armagetronad/>. Every push to this
branch rebuilds the game and republishes that site automatically
(`.github/workflows/webgl-pages.yml`).

## Branch lineage

`webgl` branches from the `v0.2.9.3.0` tag (`036daaf3`), which sits on
`trunk`'s history: the port builds on that release, with SDL1 through
emscripten's SDL1 port, the release's own autotools build, and its UDP netcode.

`trunk` has moved on to 0.4 development - SDL2 + protobuf, 666 files under
`src/` changed against 0.2.9.3.0 - so this branch deliberately does not carry
those commits: the port is not a patch set for that tree, and mixing the two
leaves a source tree that neither the 0.2.9 nor the 0.4 build system can
configure.  Giving 0.4 a web build means re-applying the same design there -
the WebSocket transport in `nSocket.cpp`, the event-loop frame driver, the three
generated-JS patches, building the `resource/` maps before the link - as new
work.

## Layout

| path | purpose |
|---|---|
| `webgl/build.sh` | configure + make + post-build JS patches, then assembles `webgl/dist/` |
| `webgl/setup_toolchain.sh` | installs the pinned emsdk and cross-builds libxml2 for wasm |
| `webgl/SDK_VERSION` | the emsdk version this port is pinned to |
| `webgl/emscripten.cache` | autoconf cache for the wasm cross-configure, generated by `build.sh` |
| `webgl/patch_*.py` | post-build fixes applied to the generated JS (see below) |
| `webgl/site/index.html` | the player page; copied into `webgl/dist/` |
| `webgl/serve.py` | local static server for `webgl/dist/` |
| `webgl/proxy/proxy.js` | WebSocket↔UDP bridge so the client can reach real servers |
| `webgl/dist/` | build output (gitignored) — this is what gets deployed |

## Building

Prerequisites: `git`, `curl`, `python3`, `make`, `g++`, `autoconf` ≥ 2.69,
`automake` ≥ 1.16, `pkg-config`. Network access is needed for the toolchain
download.

```sh
./webgl/setup_toolchain.sh   # emsdk (webgl/SDK_VERSION) + libxml2 for wasm
./bootstrap.sh               # regenerate configure / Makefile.in
./webgl/build.sh             # wasm build  -> webgl/dist/
./webgl/serve.py             # serve on http://127.0.0.1:8080
```

Environment knobs: `EMSDK_DIR`, `LIBXML2_PREFIX`, `SDK_VERSION`,
`DOWNLOAD_DIR`, `JOBS`, `CLEAN=0|1`, `PORT`.

There is no emscripten port of libxml2, and the resource manager needs it to
parse the XML resources, so `setup_toolchain.sh` cross-compiles libxml2 2.9.14
as a static library. `webgl/build.sh` runs configure with
`--host=wasm32-unknown-emscripten`, a cross-compile cache
(`webgl/emscripten.cache`) and `-D` overrides that point every install path at
the preload root; the native build is untouched.

## What was changed in the game

Wasm-specific code sits in new files or inside `#ifdef __EMSCRIPTEN__` blocks,
so native builds compile and behave exactly as before.

| area | change |
|---|---|
| `src/tools/tWasmLoop.{h,cpp}` | The blocking frame loops (`while (OnFrame()) {}`) are driven from the JS event loop via `emscripten_set_main_loop`. Nested loops, exit actions and continuations are supported; `main()` hands over to the event loop at the first loop and never returns, so the startup chain (language menu → first setup → main menu) is re-entered as steps (see `src/tron/gArmagetron.cpp`). Asyncify was deliberately not used: re-entering `main()` re-runs initialization and desyncs input. |
| `src/network/nSocket.cpp` | The browser has no UDP sockets, so each `(ip,port)` destination becomes one binary WebSocket session: proxy mode `<Module.ARM_PROXY_BASE>?target=<ip>:<port>`, direct mode `ws(s)://<ip>:<port>`. One WebSocket message is exactly one Armagetron datagram; datagrams sent while a session is still opening are queued and flushed on open. |
| `src/render/rScreen.cpp` | Display init for a canvas that follows the window: `sr_WasmWindowResized(w,h)` (exported) re-inits the display for the "desktop" screen mode; GL context/attribute handling for WebGL. `sr_DepthOffset` is inverted for this backend: WebGL only biases filled polygons and `GL_POLYGON_OFFSET_LINE`/`POINT` are no valid WebGL capability, so instead of pulling the detail lines towards the eye the fills drawn outside the offset state are pushed away from it by the same amount. |
| `src/render/rEmscriptenGLU.h` | GLU is not available in the emscripten GL stack: `gluPerspective`, `gluLookAt`, quadric/mipmap helpers reimplemented on plain GL. |
| `src/render/rSysdep.cpp`, `rGL.*`, `rDisplayList.cpp`, `rViewport.cpp` | Single-buffered WebGL swap (skip the color-buffer clear that would wipe the frame), `GL_QUAD_STRIP` handling, display-list limits, texture unit state. |
| `src/render/rTexture.cpp` | Image loading reads the file from the virtual FS (`fread` + `IMG_Load_RW`); the alpha convention matches native SDL_image, so no `IMG_InvertAlpha`. |
| `src/engine/eSound.cpp` | The SDL1 JS port has no `SDL_LoadWAV`, so a small RIFF/WAV parser loads effects; the mix callback buffer is explicitly zeroed (the JS port reuses one buffer, which otherwise accumulates samples forever). No music mixer. |
| `src/engine/eTimer.cpp`, `src/tools/tSysTime.*` | Frame timing and the clock driven from the animation-frame cadence. |
| `src/tools/tDirectories.cpp`, `tResourceManager.cpp`, `tConfiguration.cpp` | No binreloc in the browser: paths resolve to the preload root, user data to `$HOME/.armagetronad/var` (mounted as IndexedDB by the page). |
| `src/ui/uMenu.*`, `uInput*.cpp` | Menu rendering/keyboard handling for the event-loop model and browser focus rules. |
| `src/tron/*` | Startup sequence, splash/logo handling, server browser/favorites for the transport change. |
| `src/tools/wdbg.h` | Console logging that compiles to nothing unless the build adds `-DWASM_DBG`. |

## Post-build JavaScript patches

emscripten generates JS that the game cannot use as-is; `webgl/build.sh` runs
these patches on `src/armagetronad_main.js` after every link:

- `patch_sdl_convert.py` — `SDL_ConvertSurface` calls `drawImage(null)` on
  surfaces whose 2D canvas `IMG_Load_RW` discarded in `SDL.GL` mode; falls back
  to a heap-buffer copy. Without it the game froze on the first game start.
- `patch_gl_emulation.py` — the legacy GL emulation lacks immediate-mode
  `GL_QUAD_STRIP`, used for player walls; the mode is retargeted to
  `GL_TRIANGLE_STRIP`, which the wall's vertex order already is.
- `patch_emulation_fixes.py` — the fixed-function fragment shader is hardcoded
  to `precision mediump float`, which bands fog, trail fades, floor lighting
  and per-vertex wall alpha on desktop WebGL; promoted to `highp`.

The patches assert on the code they expect, so a toolchain bump fails loudly
instead of shipping a broken page.

## Page options

- Click the canvas for keyboard focus; ⛶ or double-click toggles fullscreen.
- `?args=--playback,/path.rec` — command-line arguments; files named by
  `--playback`/`--record`/`--playback-bench` are fetched from the web root and
  written into the virtual FS before `main()`.
- `?proxy=wss://host/` — WebSocket bridge base for network play, remembered in
  `localStorage` (`arma_proxy_base`). Without a proxy the client tries direct
  `ws(s)://ip:port`, which the stock server does not speak, so the hosted page
  is singleplayer by default.
- User data (settings, scores, recordings) persists in IndexedDB: the page
  mounts IDBFS over `/home/web_user`. Clearing site data resets the game.

## Multiplayer

Browsers cannot send UDP, and Armagetron's protocol is UDP, so network play
needs the bridge in `webgl/proxy/`:

```sh
cd webgl/proxy && npm install
PROXY_PORT=8091 node proxy.js                       # ws://
TLS_CERT=... TLS_KEY=... PROXY_PORT=8443 node proxy.js   # wss://
```

Then open the game page with `?proxy=ws://host:8091/` (or
`?proxy=wss://host:8443/`). The https deployment requires `wss://`, otherwise
the browser blocks the connection as mixed content. The bridge maps each
WebSocket session to the UDP socket of one server; the target can be an
address or a host name (`?target=host:port`), names are resolved by the
bridge, not by the client. This path is not covered by CI — it was verified
against a native dedicated server of the same version running next to the
dev site.

Join from the menu: Play Game → Multiplayer → Custom Connect (or a Server
Bookmark) and give the address and the port of the server. The login
handshake and the two sync rounds of a join are stepped one iteration per
animation frame (`sn_ConnectPump`, `sn_SyncStart`/`sn_SyncStep`) because the
browser only delivers the server answer while the frame function is off the
JS stack.

### Server browser

Both browse modes work through the bridge; the blocking native browse loops
are stepped per animation frame instead (`nServerInfo::PumpBrowse()`, called
from the browser menu's redraw).

- *Online Multiplayer* talks to the master servers in the master list: the
  list is `config/master.srv` from the data bundle plus every
  `ADD_MASTER_SERVER <name> <port>` (config file or console). Master names
  are resolved by the bridge. The connect, the list request and the answer
  collection all run on the frame clock; a master that does not answer is
  retried, then the list is sorted and shown.
- *LAN Multiplayer* sends a `RequestSmallServerInfo` broadcast to ports
  4534-4540, one port per 0.25 s. The bridge turns each sweep session into a
  real UDP broadcast and prefixes every answer with the answering
  server's address, which is what lets the client query and join the servers
  it just discovered. Hosts a broadcast cannot reach (separate machine,
  loopback) are added with `LAN_EXTRA=host[:port][,host[:port]]` on the
  bridge: every sweep datagram is replayed to them as a unicast.

## Limitations

- No background music: the SDL1 JS port has no mixer, so only sound effects
  play.
- The toolchain is pinned (`webgl/SDK_VERSION`) because the build depends on
  `-s LEGACY_GL_EMULATION=1`, which newer emscripten releases are phasing out.
- Single-threaded: no pthreads/SharedArrayBuffer, so no COOP/COEP requirement.
- Network play needs the bridge, as above.
- LAN server browse stays empty: it probes the local network with a broadcast,
  and the bridge maps one WebSocket to one server address.
- Frame rate is bounded by the fixed function emulation (every immediate mode
  call is re-tessellated in JS) and by the browser's software renderer when no
  GPU is available. Measured in headless Chrome with SwiftShader: menus run at
  ~60 frames/s, a round at ~1.6 frames/s. The HUD `FPS:` readout and the game
  clock both follow that rate correctly, so a low number is the renderer, not a
  broken timer.
- The top level main menu cannot be left. The native build exits the process
  there; a page has no process to exit into, so leaving that menu re-opens it
  and its "Exit game" item is not shown.

## Deployment

GitHub Pages must build from Actions (repository **Settings → Pages → Build and
deployment → Source: GitHub Actions**). Then a push to `webgl` runs
`WebGL build & Pages`: it builds the toolchain, bootstraps autotools, builds
the wasm, uploads `webgl/dist/` as a Pages artifact and publishes it at
<https://smarioman.github.io/armagetronad/>. Pull requests to this branch build
and keep the site build checkable but do not deploy.
